# ClipDeck 产品设计

日期：2026-10-06。状态：具体设计与独立复核修正，不代表产品已实现。此前的产品方案确定了文字剪视频方向，工具核查记录了本机可用的转写与媒体引擎。用户随后明确要求“未就绪工具就让他就绪”“没问题再继续”。按现有桌面方案推进 macOS Apple Silicon 首版，补齐并实测开发工具；其他平台不以本机结果代替验证。

## 用户与成果

访谈、播客、课程和口播创作者从多个长素材中挑选有用的表达，通过读文字完成粗剪。用户不需要先学习复杂时间线：导入自己的视频，等待本地转写，选几句话，调整顺序与切点，预览并得到可播放的 MP4。

第一版交付可运行的桌面编辑器、可保存恢复的项目、真实媒体导出、开发与安装说明，以及用公开可再分发或自己生成的测试素材制作的演示。演示必须提供自己的文件入口。用户将目标提高为有 500+ stars 潜力与硬水准的开源产品：需要公开代码、可验证的安装包、真实操作演示、可复现的媒体正确性与长内容性能基准，不能只交付外观样稿。获得 stars 是后续用户采用与传播的结果，不作为可保证的工程验收数字。

## 完整操作

1. 新建项目，选择或拖入多个本地视频。读取名称、时长、尺寸、旋转和音轨；导入成功项留在素材栏，失败项显示具体原因。
2. 检查本地语音模型。首版转写 worker 接受完整且校验通过的 CTranslate2 模型目录；已有模型可以直接使用。没有模型时明确提供选择本地模型和下载官方模型的操作，显示大小、进度及取消。模型下载固定仓库、revision、文件清单和摘要；仅模型准备需要联网，媒体处理留在本机。
3. 素材进入转写队列，显示等待、加载、处理、取消或失败状态。识别结果逐段出现，保留句子与单词的时间锚点。用户可以编辑已有素材时等待其他素材完成。
4. 点击文字定位画面；划选连续文字，试听后加入选段序列。一次选择来自一个素材，可重复加入同一段；不同素材的选段可以排列在一起。无语音或无音轨素材可在视频预览中设定入点、出点，添加手动选段。
5. 拖动重排，并提供键盘向前/向后移动按钮。每段可编辑名称、调整前后切点、循环试听、移除及撤销。切点可以超出所选文字的默认范围，但必须保持在原素材有效时长内。
6. 原素材试听与成片预览分别标明。连续成片预览用同一剪辑计划生成较低分辨率代理，保持相同片段边界、目标画幅、旋转、留边和声音；显示准备进度，计划修订后旧缓存失效。播放显示原素材位置与整条成片的位置，跳转与暂停维持明确的当前选段。
7. 选择输出横屏 1920×1080、竖屏 1080×1920 或方形 1080×1080，均为 30 fps；原画面等比适配，使用留边，第一版不自动裁掉人物。确认路径后导出 MP4。
8. 导出显示当前阶段、实际处理进度和取消；成功后可播放并定位成片。失败可查看原因并重试。导出使用启动时的计划快照，之后编辑不会改变本次输出。
9. `.clipdeck` 为引用式 JSON 项目，不包含视频；保存素材相对路径和内容指纹。跨电脑移交时同时带上原素材，找不到的文件可重新关联。另存后切换当前项目保存路径；应用另留包含项目 ID、修订号和原路径的自动恢复副本。重新打开后恢复素材引用、转录、选段顺序、切点和输出设置，旧恢复副本不得静默覆盖更新的项目。素材移动或修改时要求重新关联或重新转写，不悄悄使用错片。

## 工作台

顶部仅保留项目名称、保存状态、打开/保存和导出。左侧为窄素材栏，中间为主要转录区，右侧为视频与选段检查器，底部为持续可见的选段序列。窗口缩小时检查器改为可切换面板，关键编辑和导出入口保持可见。

视觉方向为低饱和墨灰外框、阅读区清楚的明暗层级、对齐的数字时间码与少量暖色强调。画面、转录内容和选段承担视觉主体；控件按真实编辑任务组织，不堆积装饰卡片。选中文字、当前播放位置和已加入片段需要不同的形状或标识，不能只靠颜色区分。

空项目直接展示选择和拖入视频。其他状态包括无语音、正在转写、失败重试、取消、缺失素材、没有选段、导出中和输出完成。长文件名可截断并查看完整名称；长转录滚动时工具栏保持可用。按键可操作导入、播放、加入选择、重排和删除，焦点必须可见。减少动效模式取消位移效果。

## 组件与数据

建议采用 Electron、React/TypeScript、本地任务管理器、Python faster-whisper 转写进程和 FFmpeg 输出进程。首版先用已经验证可离线加载的 faster-whisper；转写接口保持独立，后续可以替换为 whisper.cpp。页面操作不能直接调用任意文件系统或命令。

- **素材 Asset：**稳定 ID、文件引用、文件状态、媒体参数和内容指纹。文件引用与界面显示名称分别保存。导入和重新关联都重新探测媒体。
- **转录 Transcript：**素材 ID、内容指纹、转录修订号、识别语言、分段、单词、时间戳、模型身份/摘要、引擎版本和识别参数。句子按标点和停顿组织，不把每个识别 segment 一律当成句子。中文与英文都保留原始时间锚点；修订显示文字不自动改变时间。
- **选段 Cut：**稳定 ID、素材 ID、来源内容指纹、转录修订号、起止毫秒、所选单词 ID、显示文本、备注及待复核状态。手动选段的单词列表为空。顺序是独立数组，排序不会改原素材时间。
- **项目 Project：**格式版本、项目 ID、修订号、素材、转录、选段、输出设置与保存时间。导入项目需验证格式、资源大小和所有时间范围，不执行文件中的任何代码。
- **任务 Job：**ID、类型、状态、阶段、已处理时长、错误和取消状态。任务状态来自实际进程事件，不能用定时器伪造进度。
- **剪辑计划 AssemblyPlan：**项目修订号、按顺序排列的选段快照及来源指纹、输出参数、每段输出帧数/音频采样数和累计边界。预览与导出读取同一份计划定义；计划快照不等于把原素材复制成不可变文件。

编辑时间字段使用整数毫秒，每个选段满足 `0 <= start < end <= assetDuration`。计划按每段 `frameCount = ceil(durationMs × 30 / 1000)` 量化，至少一帧；48 kHz 音频目标为 `frameCount × 1600` samples。保留精确原素材区间，只补最后选中的画面和静音到目标长度，不越过选段结束读取新内容。极短区间若没有有效画面，显示最小可用范围并要求调整，不能让空视频流进入拼接。总时长是整数帧数之和除以 30，累计边界使用帧数/采样数，不反复累加浮点数。有缺失素材、待复核选段、无效范围或空序列时，成片预览和导出前给出可修正的原因。

## 本地处理与失败恢复

转写进程使用明确本地模型路径和离线加载参数，要求本地 tokenizer 与模型文件完整；缺文件直接报错，不能触发隐式远程加载。使用 VAD 时将相应 ONNX 文件和运行库纳入资源清单。输出结构化任务事件，模型准备、音频解码和语音识别是不同阶段；单个片段完成后才更新已处理时间。取消时结束进程并等待关闭，取消结果不得落成完整转录。

FFmpeg 从原素材的选定范围读取，重新编码；统一尺寸、像素比例、帧率、像素格式、音频采样率和声道。没有音轨的片段按片段时长补静音。各片段的音视频时间戳归零后再拼接，处理视频旋转信息，最终输出 H.264/AAC MP4。

所有进程使用参数数组启动，不拼接 shell 字符串。持续读取输出，限制任务并发，清理任务自己的临时文件。导出目标的真实路径与文件身份不得等同于任何原素材；覆盖已有输出需通过保存对话框明确确认。文件先写入同一目标目录的临时路径，任务经过处理、验证、提交、完成。取消作用于编码和验证进程，提交前再次检查取消状态；原子重命名是完成边界，提交后显示已完成。只有输出可完整解码、帧数与量化计划时长符合要求后才提交。取消、失败、应用退出或重试不能把残缺输出报告为完成。

项目保存使用临时文件和原子替换，保存失败保留未保存状态。退出时提示尚未完成的任务。重新打开项目时核对素材状态；缺失素材可逐项重新关联。同内容重新关联保留转录和选段，不同内容使旧转录失效，相关选段进入待复核状态，重新转写并检查/替换前禁止成片预览与导出。即使替换素材时长相同也不能跳过。任务读取前核对来源指纹，处理中检测到素材变化就失败，不悄悄使用修改后的内容。

本地媒体地址只接受已导入素材的 ID，并验证请求来源。使用隔离的 preload、受限 IPC、页面内容安全策略和受控资源协议，限制页面导航与新窗口。[Electron 安全说明](https://www.electronjs.org/docs/latest/tutorial/security)、[协议说明](https://www.electronjs.org/docs/latest/api/protocol)

## 可安装性

开发工作流需要明确的项目内依赖准备与启动方式，不能硬编码开发者的用户目录。应用内展示引擎和模型是否就绪，并给出具体恢复动作。

桌面交付需要在本机实际启动的 macOS ARM64 应用；应用随包携带媒体二进制和封装后的转写 worker，原生文件与动态库放在实际资源目录中。开发模式另提供项目内准备流程，不能把开发者现有 PATH/Python packages 当成分发依据。模型缓存独立于应用包，下载可取消并校验，重装不重复丢失缓存。记录媒体引擎、转写库和模型的版本与许可。

签名、公证、Windows 和 Intel Mac 构建需要各自的条件与实机证据。没有这类证据时下载说明不得宣称已支持；不以浏览器页面启动成功证明安装包可用。
