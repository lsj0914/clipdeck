# ClipDeck Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish a substantial open-source local text-based video editor with a complete real-media workflow, verified macOS app, professional interface, reproducible quality evidence and a credible adoption case for 500+ stars.

**Architecture:** Electron main process owns files, project state and cancellable jobs. React consumes a restricted typed preload API; native media workers and an offline transcription worker produce structured events. A deterministic assembly plan drives both low-resolution preview and final MP4 output.

**Tech Stack:** Node 24, Electron 44.5.1, React 19.3.0, TypeScript 7.0.2, Vite 8.3.3, Vitest 5.0.3, esbuild 0.28.2, TanStack Virtual 3.14.13, FFmpeg/ffprobe 9.0.2, Python 3.12, faster-whisper; verified whisper.cpp 1.9.4 is available for native engine evaluation. Dependencies are pinned by lockfile; packaged native versions are recorded.

**Spec:** [2026-10-06-clipdeck-design.md](../specs/2026-10-06-clipdeck-design.md)

## Global Constraints

- macOS ARM64 is the first actually verified desktop target. Do not claim other platforms are verified without build/run evidence.
- Own-file import, full offline transcription after model preparation, text selection, manual silent-video selection, reordering, cut adjustment, continuous preview, export, save/reopen and recovery are required.
- Output is H.264/AAC MP4 at 30 fps: landscape 1920×1080, portrait 1080×1920, square 1080×1080, equal-aspect fit with padding.
- Canonical frame count is `ceil(durationMs * 30 / 1000)`, minimum one frame. Audio is 48 kHz, 1600 samples per output frame. Never read beyond the selected source interval to fill padding.
- No shell command construction from file names. No arbitrary renderer filesystem/command APIs. No media uploads or implicit model downloads.
- Output is committed only after decoding and plan verification. Cancellation applies through validation until atomic commit. Original sources must not be overwritten.
- Changing content invalidates related transcripts/cuts even when duration is unchanged. Missing media can be relinked by content identity.
- Install all explicitly requested missing development tools and verify actual operations before using them. Dependency failure is repaired rather than bypassed.
- Ship a tested app with media engines and transcription worker in its resources; development-only PATH/package caches do not prove packaging.
- Use the external design skills for the actual workbench and inspect real rendering; use independent technical and visual review. No tests that merely mirror CSS.
- README novelty claims require primary-source support. Stars potential is a product target, never a guaranteed test result.

## Review Focus

- Equal-duration replacement media must invalidate old selections; include an actual replacement-file test in Task 2.
- Non-integer frame boundaries in dozens of short cuts must not accumulate drift; pin exact frame/sample totals in Task 3.
- Cancel at encoder exit, during validation and just before commit must not publish a partial file; exercise each point in Task 3.
- Untrusted project JSON, custom protocol paths and IPC payloads must not expose arbitrary host files or processes; exercise rejection in Tasks 1 and 2.
- A fresh app data directory with a restricted PATH and empty model cache must complete setup and later offline export; exercise packaged runtime in Task 6.

## File Boundaries and Contracts

- `src/shared/contracts.ts`: serializable domain, job, snapshot, edit-command and preload API types; no filesystem imports.
- `src/domain/project.ts`, `assembly.ts`, `selection.ts`: pure validation, edits/history, deterministic frame/sample plan, text-range mapping.
- `src/main/main.ts`, `preload.cjs`, `ipc.ts`, `media-protocol.ts`: native window, restricted bridge and approved-media serving.
- `src/main/services/{workspace,media,models,transcription,jobs,render,storage}.ts`: authoritative state, source probing/identity, model readiness, worker adapter, process lifecycle, rendering and atomic persistence.
- `src/renderer/{App.tsx,app.css,components/*,hooks/*}`: professional editor; consumes only `window.clipdeck`.
- `worker/transcribe.py`, `worker/requirements.txt`: deterministic offline worker with JSONL on stdout, diagnostics on stderr.
- `scripts/{build-desktop,prepare-electron,prepare-worker,package-native,verify-package,media-benchmark}.mjs`: repeatable build, readiness repairs, resource preparation, packaging and evidence.
- `tests/{domain,services,integration}` and `docs/verification/`: meaningful tests and actual runtime evidence.

`ClipDeckAPI` is the shared boundary: `getSnapshot(): Promise<WorkspaceSnapshot>`, `importMedia(): Promise<WorkspaceSnapshot>`, `importDroppedFiles(files: File[]): Promise<WorkspaceSnapshot>`, `applyEdit(command: EditCommand): Promise<WorkspaceSnapshot>`, `transcribe(assetId: string, language: 'auto'|'en'|'zh'): Promise<string>`, `preparePreview(): Promise<string>`, `exportVideo(): Promise<string>`, `cancelJob(jobId: string): Promise<void>`, `openProject(): Promise<WorkspaceSnapshot>`, `saveProject(asNew?: boolean): Promise<WorkspaceSnapshot>`, `relinkMedia(assetId: string): Promise<WorkspaceSnapshot>`, `chooseModel(): Promise<WorkspaceSnapshot>`, `downloadModel(): Promise<string>`, `revealExport(jobId: string): Promise<void>`, and `subscribe(listener: (snapshot: WorkspaceSnapshot) => void): () => void`.

`WorkspaceSnapshot` carries project metadata, safe asset descriptors, transcripts/cuts, output settings, model status, jobs and save state. Source paths remain main-process owned; renderer uses approved media URLs. `EditCommand` supports `addCut`, `updateCut`, `removeCut`, `reorderCuts`, `setOutput`, `renameProject`, `undo` and `redo`. The exact field definitions are established in Task 1 before dependent tasks start.
