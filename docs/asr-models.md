# Local transcription models and corrections

ClipDeck defaults to the multilingual small model. Large v3 turbo is an optional, explicitly acquired model with a larger download. Both run locally on CPU after the complete pinned directory passes size and SHA-256 checks in main and again in the worker. Choosing a local folder recognizes only these known complete manifests. Model downloads publish the directory and selected-model settings together; cancellation or failure retains a previously ready model.

The [pinned turbo model card](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo/blob/0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf/README.md) identifies an MIT-licensed CTranslate2 conversion of OpenAI Whisper large v3 turbo. The stored weights are FP16; ClipDeck selects CPU int8 inference. The [pinned small card](https://huggingface.co/Systran/faster-whisper-small/blob/536b0662742c02347bc0e980a01041f333bce120/README.md) also declares MIT. Whisper recognition models are acquired separately and are not bundled in the application runtime archives. The separate punctuation model described below is bundled. Per-file URLs, byte sizes and hashes live in `src/main/services/models.ts` and `worker/transcribe.py`; the aggregate digest hashes the ordered `{name,bytes,sha256}` list. Changing either list requires matching main/worker changes and new evidence.

`ModelStatus.available` is the two-choice catalog, not a claim that either model is installed. Only `status: "ready"` with `choice` identifies the currently verified selected model. The existing `MODEL_MANIFEST` and `MODEL_DIGEST` exports continue to mean small.

The restricted bridge retains its 16 methods. `downloadModel(choice?)` defaults to small. `transcribe(assetId, language, {vocabulary?}?)` uses the active verified model. Renderer arguments cannot supply model paths, URLs, decoder settings or prompts. Vocabulary accepts at most 1,000 Unicode characters and 64 nonempty comma, Chinese comma, semicolon or newline separated terms. The actual local model tokenizer bounds the combined prompt/hotword context to 128 tokens. Explicit `zh` and automatic detection of Chinese request a Simplified Chinese prompt; this is a prompt preference, not a guarantee of script or recognition accuracy. Other language selections receive no forced Chinese prompt. Automatic language detection uses VAD speech before choosing the Chinese or English prompt; an empty speech result returns an empty transcript. English recognition receives a punctuation style prompt. The transcript persists the vocabulary, language, model digest, engine version, prompt preference and applicable punctuation identity. Jobs do not store retry options.

Chinese punctuation runs automatically after successful recognition and before the complete transcript is committed. The local CT-Transformer model is `iic/punc_ct-transformer_zh-cn-common-vocab272727-onnx`, revision `8f239ff78c6267c4d859233e7eb3bbdb68c61824`; `model_quant.onnx` SHA-256 is `e6cd8399bf7d0e75f8d9af4a107310e1968ecab1d50135e765b8f0265b27a83d`. Both weights and vocabulary are checked for size and hash. The bounded window mapping restores Chinese commas, sentence stops and questions while preserving recognized letters, numbers, whitespace, quotes, meaningful decimal/version separators, word IDs and timestamps. It does not repair recognition errors. Main independently checks lexical content and anchor ownership, then persists the model identity in `parameters.punctuation`. Missing or corrupt punctuation resources fail the job and retain the previous complete transcript; there is no silent unpunctuated replacement. English uses Whisper punctuation directly; this Chinese model is not applied to English. Old saved transcripts remain unchanged until the user requests re-transcription.

The worker requires the pinned Python 3.12.15 runtime and packages. Source video is predecoded by FFmpeg 9 to 16 kHz mono PCM, then passed as a local NumPy waveform. Inference uses local model files, VAD, CPU int8, four threads and beam size five under the existing OS network denial. Early `ORT_DISABLE_TELEMETRY=1`, ONNX telemetry API disablement and offline Hugging Face flags remain enabled. Missing or corrupt resources fail explicitly; there is no model-name fallback.

Inference explicitly sets `condition_on_previous_text=False` on both models. Generated recognition from an earlier window is not reused as the next window's prompt. The initial prompt and explicit vocabulary hints remain supplied; no repetition penalty or token deletion is applied. The [pinned faster-whisper implementation](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py) documents reduced repetition/timestamp failure-loop risk with this setting, with a tradeoff in text consistency across windows. The Simplified Chinese initial prompt applies to the first window, as upstream defines it; vocabulary hints remain available to later windows.

New transcripts persist `parameters.conditionOnPreviousText: false`, and main requires the worker's completion to report that setting before replacement. The optional boolean is retained on project save/reopen. Older projects may omit it; omission stays unknown rather than being relabeled with the new behavior. Recognition text and timestamp normalization remain unchanged.

Some recognized text has no positive word duration. ClipDeck keeps that text and the measured timestamps, while marking the anchor that receives folded untimed text with `timingNeedsReview: true`. The same marker follows leading text transferred across worker batches. Both worker ready and complete packets must report supported `wordTimingReview: true`; new transcripts retain that optional parameter. These fields record how uncertainty was handled, not an accuracy score or a guarantee that unmarked words are correctly aligned. Older projects without this provenance stay unknown.

Marked word anchors stay readable, searchable and correctable. Text corrections, saving, reopening and undo/redo retain their timing markers. A word-derived selection cannot use an uncertain start or any uncertain anchor contributing its maximum end as an automatic cut or short audition. The interface offers an editable time range with up to two seconds of listening context on each side; those suggested values do not replace the transcript's timestamps. Entirely untimed text remains readable and searchable during live processing and after completion, but is display-only; its manual review path becomes available after completion. Recognition and timing still need listening review before a final edit.

Re-transcription leaves the existing complete transcript visible until successful atomic replacement. A failed or cancelled job retains it. A successful replacement increments its revision, assigns a new ASR `originId`, and makes cuts from the previous recognition reviewable.

Text correction uses `correctTranscript` with the source ID/fingerprint, current transcript revision and exact immutable word IDs. Each replacement changes word text only; word/segment IDs and all source timestamps remain unchanged. Derived segment and applicable cut labels follow corrected words. Explicit custom cut labels are retained; legacy labels differing from their derived words are inferred custom. Undo/redo restores text within the same ASR origin with increasing revisions, so an older history entry cannot resurrect text after later re-transcription. History shares immutable transcript references and unchanged word objects. Project persistence includes corrected text and provenance. English word replacements should preserve their original leading separator.

Recorded EN/ZH checks on both choices exercise the real offline worker and native adapter. Their evidence is in [asr-quality.json](verification/asr-quality.json). Chinese checks include supplied vocabulary and are hint biased; successful anchor matching is a regression gate, not an accuracy metric. A separate authorized bounded private diagnostic compared identical PCM with the upstream default and independent windows. It did not reproduce the exact reported repeated-character loop, but the longer prefix exposed severe timestamp packing under defaults that the candidate avoided while retaining a comparable number of timed words and the speech span. Those recordings, texts, paths and fingerprints remain outside the repository; the original video/project were not modified. This is evidence for the narrow decoding policy, not proof of whole-recording accuracy. No CER/WER or general speed/accuracy claim is made.
