## What changed

This update changes first-use and replacement-transcription feedback. A pending request starts as waiting, with indeterminate progress, rather than displaying a previous job's 100% or cancellation. Controls cancel the current job. Source status gives missing/changed media priority, then active work, and distinguishes a matching existing transcript from a first attempt that was cancelled. Existing transcripts remain available while a replacement is attempted; failed attempts show the current error. Twelve targeted renderer cases and two independent boundary cases passed; the scoped code review found no Critical or Important issue. The complete local suite passed 444 tests, with 16 recording-fixture-gated skips, and coherent typecheck/build passed before packaging.

## Restricted-network scope

The separate new run used Node API guards, Electron session controls and a rejecting proxy, plus the sandboxed worker and media commands. Before/after Node, Chromium, renderer and DNS canaries remained rejected, and local canary hit counts did not increase during the workflow. All 28 recorded workflow child launches were retained. No natural workflow network attempt was recorded. Recognition, preview, native export and reopen completed under this defined method with the already selected local model.

This proves the performed workflow under those controls. It is **not whole-Electron kernel network denial**, a firewall audit, or a proof about every possible library/path. The harness deliberately reports method proof rather than automatically accepting the product. Raw profiles and traces remain private.
